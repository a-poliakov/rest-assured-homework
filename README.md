# Постановка задачи
Домашнее задание
В данном задании предлагается покрыть тестами REST API сервиса pet-clinic.

Сервис pet-clinic — самый известный демо-пример фреймворка java spring (пример).

Open api сервиса можно изучить по ссылке.

Создайте репозиторий на github, склонируйте себе на компьютер.

Необходимо создать пустой maven-проект в созданном github репозитории, подключить к нему библиотеки junit и rest-assured.

Все следующие шаги необходимо выполнять в директории src/test.

Предварительная настройка системы (с использованием rest api сервиса через библиотеку rest assured):
1. Добавить одного пользователя с ролью admin
2. Добавить 2 владельцев питомцев
3. Добавить 3 вида питомцев
4. Добавить 5 питомцев
5. Создать 2 специализации ветеринаров
6. Создать 3 ветеринара
Необходимо протестировать следующие сценарии:
- Позитивный сценарий
- Негативный сценарий

- Позитивный сценарий:

Через UI пользователь делает следующее:
- выбирает владельца питомца
- выбирает питомцев, которых нужно записать на прием
- выбираются ветеринары с соответствующей специализацией
- создать записи на прием к выбранным ветеринарам
- пользователь ожидает увидеть созданную запись на прием
Действия через UI могут быть осуществлены через вызовы REST API:
- GET /owners/{ownerId}
- GET /vets
- POST /owners/{ownerId}/pets/{petId}/visits
body:
{
“date”: date,
“description”: “vet specialization” + “vet id”
}

Проверить:

существование созданной записи (visit) с заданным ранее description и date

Негативный сценарий:

Не забывайте, что надо писать тесты и на валидные, и на недопустимые данные.

Рассмотрим следующий негативный сценарий:
- создать записи на прием
- попытаться получить записи для несуществующего питомца


Инструкция:
сделать fork репозитория
склонировать сделанный fork себе на компьютер
создать ветку homework-rest-assured
написать код тестов, реализовав позитивный и негативный сценарии (ссылка на api тестируемого сервиса)
сделать push ветки на github
в репозитории создать pull request (source - ветка в вашем репозитории, target - ветка мастер в репозитории)

Результат:
- ссылка на Pull Request в github-репозитории с реализованными тестами
- реализована предварительная настройка
- реализованы позитивный и негативный сценарии тестов (выполнение действий и проверки)
- CI пайплайн в рамках созданного pull request должен быть успешным (зеленая галочка)

## Подключенные зависимости и плагины

- плагин для инструмента сборки Maven, который запускает юнит-тесты во время стадии test жизненного цикла проекта
- rest-assured - библиотека для тестов REST-сервисов
- json-schema-validator - это инструмент для валидации данных JSON по схеме (без этого использование объекта для перадачи в body не работало)
- junit-jupiter-engine - это основной движок тестирования для JUnit 5, отвечающий за запуск тестов 
- junit-jupiter-params - библиотека для создания параметризованных тестов в JUnit 5 (для  @Tag и @DisplayName)
- lombok - библиотека для сокращения кода в классах и расширения функциональности языка Java. (без неё Builder и использование объекта для перадачи в body не работало)
